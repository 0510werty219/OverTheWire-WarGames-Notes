# Linux 权限位记法速查表

>覆盖 `ls -l` / `stat` / `chmod` / `find -perm` / `umask` 里出现的所有权限记法

---

## 一、权限字符串怎么读（10 个字符）

```text
-rwsr-xr-x
│└┬┘└┬┘└┬┘
│ │  │  └── 其他用户 other (o)
│ │  └───── 属组 group (g)
│ └──────── 属主 user (u)
└────────── 文件类型
```

**特殊位不占独立字符位置**，而是挤在对应身份的 x 位上：setuid → u 位，setgid → g 位，sticky → o 位。

## 二、第 1 位：文件类型

| 字符 | 类型 | 例子 |
|:-:|:-:|:-:|
| `-` | 普通文件 | readme、密码文件、ELF 程序 |
| `d` | 目录 | 目录本身也是一种文件 |
| `l` | 符号链接 | 内容只是一个路径字符串 |
| `c` | 字符设备 | `/dev/null`、`/dev/tty` |
| `b` | 块设备 | `/dev/sda` |
| `p` | 命名管道 FIFO | `mkfifo` 创建 |
| `s` | 套接字 socket | `/run` 下常见 |

## 三、后 9 位：r / w / x

| 字符 | 值 | 对普通文件 | 对目录 |
|:-:|:-:|:-:|:-:|
| `r` | 4 | 读取文件内容 | 列出目录内的**文件名** |
| `w` | 2 | 修改文件内容 | 增删、重命名目录内的条目 |
| `x` | 1 | 执行（`execve`） | 进入并访问目录内的文件（拿到 inode） |
| `-` | 0 | 无此权限 | 无此权限 |

>[!WARNING]
>
>`r` 和 `x` 在目录上是**两件事**：只有 `r` 没有 `x`，你能 `ls` 出一堆名字但 `ls -l` 全是 `?????????`，`cat` 任何一个都会 `Permission denied`。
>
>**删除文件的权限不看文件本身，只看它所在目录有没有 `w` + `x`**。所以一个 `chmod 000` 的文件，只要目录可写你照样能删掉它 —— sticky 位就是用来堵这个洞的。

## 四、特殊位：显示规则与生效条件

### 4.1 大小写 = 原来那个 x 位在不在

**小写说明对应身份本来就有 x 位，大写说明本来就没有。**

特殊位不新增字符位置，而是直接**占用对应身份的 x 位那一格**：那个位置原本是 `x`，就被改写成小写 `s`/`t`；原本是 `-`，就被改写成大写 `S`/`T`。所以大小写是“原位状态”的显示器。

| 显示 | 占用位置 | 特殊位状态 | **该位置原本的 x 位** | 完整例子 | 数字 |
|:-:|:-:|:-:|:-:|:-:|:-:|
| `s` | 属主 u | setuid 已置位 | **有**（原本是 `x`） | `-rwsr-xr-x` | 4755 |
| `S` | 属主 u | setuid 已置位 | **无**（原本是 `-`） | `-rwSr--r--` | 4644 |
| `s` | 属组 g | setgid 已置位 | **有**（原本是 `x`） | `drwxrwsr-x` | 2775 |
| `S` | 属组 g | setgid 已置位 | **无**（原本是 `-`） | `-rw-r-Sr--` | 2644 |
| `t` | 其他 o | sticky 已置位 | **有**（原本是 `x`） | `drwxrwxrwt` | 1777 |
| `T` | 其他 o | sticky 已置位 | **无**（原本是 `-`） | `drwxrwxrwT` | 1766 |

>[!TIP]
>
>反向读法：**看到小写 $\rightarrow$ 该身份对它本来就有执行权限；看到大写 $\rightarrow$ 该身份连执行都没有。**
>
>顺带一个操作顺序坑：先 `chmod 4755` 再 `chmod 644`，后面那句会把 u 的 x 位抹掉，小写 `s` 当场变大写 `S`。
>想加特殊位又不想踩这个坑，就用符号法 `chmod u+s`，它不碰已有的 rwx。

### 4.2 那它生效吗

| 位置 | 小写 | 大写 | 大写时到底生效吗 |
|:-:|:-:|:-:|:-:|
| 属主 `u` 的 x 位 | `s` | `S` | **不一定失效**。只说明 u 的 x 位没开；只要 g 或 o 还有 x，文件仍可执行，setuid 照样把 euid 换成属主 |
| 属组 `g` 的 x 位 | `s` | `S` | **一定不生效**。Linux 把「有 S_ISGID 但无 S_IXGRP」重新定义为强制锁标记（`inode(7)`），此时该位不归 setgid 用 |
| 其他 `o` 的 x 位 | `t` | `T` | **无意义**。现代 Linux 对普通文件忽略 sticky；目录上 o 没有 x 时其他人根本进不去 |

**内核依据**（`fs/exec.c` 的 `bprm_fill_uid()`）：

```c
if (mode & S_ISUID)                                          /* 只看一个位 */
        bprm->cred->euid = inode->i_uid;

if ((mode & (S_ISGID | S_IXGRP)) == (S_ISGID | S_IXGRP))     /* 两个位都要 */
        bprm->cred->egid = inode->i_gid;
```

>[!IMPORTANT]
>
>`ls` 显示的大写 `S` 只是 coreutils 的**字符串渲染规则**（检查「特殊位置位了但对应 x 位没有」），
>跟内核的**生效判定**是两套逻辑。确认真实行为请用 `stat -c %a` 拿到数字再自己推位，别只信 `ls`。

### 4.3 三个特殊位一览

| 位 | 值 | 作用对象 | 效果 |
|:-:|:-:|:-:|:-:|
| setuid | 4000 | 可执行文件 | 执行时 `euid` = 文件属主，例：`/usr/bin/passwd` |
| setgid | 2000 | 可执行文件 | 执行时 `egid` = 文件属组 |
| setgid | 2000 | **目录** | 目录内新建的文件和子目录**继承目录的属组**，且子目录连 setgid 位一起继承 |
| sticky | 1000 | 目录 | 人人可写，但只有文件属主（或目录属主 / root）能删自己的文件，例：`/tmp` |

## 五、数字记法

**后三位**：每组 `r=4 w=2 x=1` 相加。

```text
rwx r-x r-x
│   │   └── o: 4+0+1 = 5
│   └────── g: 4+0+1 = 5
└────────── u: 4+2+1 = 7        →  755
```

**最高位**（可省略）：`4×setuid + 2×setgid + 1×sticky`

| 数字 | 等价写法 | 含义 |
|:-:|:-:|:-:|
| `755` | `0755` | 普通可执行，无特殊位 |
| `4755` | `u+s` | setuid，如 `/usr/bin/passwd` |
| `2755` | `g+s` | setgid，如共享目录 |
| `1777` | `o+t` | sticky，如 `/tmp` |
| `6755` | `u+s,g+s` | setuid + setgid |
| `7777` | 全开 | 三个特殊位都置上（危险信号） |

## 六、`chmod` 符号记法

三个维度自由组合：`chmod [谁][操作][权限] 文件`

| 谁 | | 操作 | | 权限 |
|:-:|:-:|:-:|:-:|:-:|
| `u` 属主 | | `+` 加上 | | `r` `w` `x` |
| `g` 属组 | | `-` 去掉 | | `s` setuid/setgid（随前面的 u/g 而定） |
| `o` 其他 | | `=` 直接赋值 | | `t` sticky |
| `a` 全部（默认） | | | | `X` 见下方 |

```bash
chmod u+s file      # 加 setuid
chmod g+s dir       # 加 setgid
chmod o+t dir       # 加 sticky
chmod g-w file      # 去掉属组写权限
chmod u=rw file     # 属主严格等于 rw，其他位不变
chmod a+X 目录/     # 见下方
```

>[!TIP]
>
>**大写 `X` 是个好东西**：`chmod -R a+X 目录/` 只给「目录」和「本来就有任一执行位的文件」加 x，
>不会把一堆普通文本文件误变成"可执行文件"。批量授权时用它比 `a+x` 安全得多。

## 七、`find -perm` 的三种模式

| 写法 | 含义 |
|:-:|:-:|
| `-perm 755` | **精确等于** 0755 |
| `-perm -755` | **全部包含**：u/g/o 的这些位都为 1（AND 语义） |
| `-perm /222` | **任意命中**：r/w/x 中任意一位为 1 即可（OR 语义；旧写法 `+222` 已废弃） |
| `-perm -4000` | setuid 文件（提权枚举第一步） |
| `-perm -2000` | setgid |
| `-perm -6000` | setuid 或 setgid |
| `-perm -1000` | sticky |

```bash
find / -perm -4000 -type f 2>/dev/null    # 枚举全盘 setuid 可执行文件
```

>[!NOTE]
>
>`-perm` 只看权限位；`-executable` / `-readable` / `-writable` 是调 `access()` 问内核，
>**会把 ACL 算进去**，更贴近"我到底能不能执行它"。文件挂了 ACL 时 `ls -l` 权限末尾会显示 `+`，
>此时只看 9 个位会误判，优先用 `-executable`。
>
>以 root 运行时 `-executable` 几乎恒为真（root 只要任一 x 位就能执行），此时反而要用 `-perm`。

## 八、`umask` 速查

新建文件 `= 0666 & ~umask`，新建目录 `= 0777 & ~umask`

| umask | 新建文件 | 新建目录 | 典型场景 |
|:-:|:-:|:-:|:-:|
| `022` | 644 | 755 | 大多数发行版默认 |
| `002` | 664 | 775 | 组内协作 |
| `027` | 640 | 750 | 不给其他人任何权限 |
| `077` | 600 | 700 | 最严格，只有自己 |

>[!TIP]
>
>文件默认从 `666` 而不是 `777` 起步，**所以新建文件默认没有执行位** —— 可执行必须显式产生
>（编译、`chmod +x`、`install -m`）。这是防误执行的安全设计。

## 九、六个反直觉的坑

1. **删文件看目录的 `w`，不看文件自己的权限。**
2. **`cp` 会丢 setuid/setgid/os 特殊位**，要保留得用 `cp -a` 或 `--preserve=mode`。
3. **非 root 往 setuid 文件里写一次内容，内核会自动清掉 S_ISUID/S_ISGID** —— 防篡改设计。
4. **脚本上的 setuid 无效**：内核 `execve` 带 `#!` 的脚本时直接忽略 setuid/setgid 位（真正执行的是解释器）。
5. **属主位的大写 `S` 不等于失效**，只有三个 x 位全无时才真失效（见第四节）。
6. **`ls` 的显示 ≠ 内核的判定**，一个只看位组合，一个看 `bprm_fill_uid()` 的条件。

## 附：三个 uid 与 setuid 的关系

| 概念 | 含义 |
|:-:|:-:|
| `ruid` real uid | 谁启动的进程（真实身份） |
| `euid` effective uid | **内核检查权限时用的身份**，setuid 改的就是它 |
| `suid` saved uid | 从 setuid 程序启动时保存下来的 euid，允许程序在两者间切换 |

```bash
id        # uid=11019(bandit19) euid=11020(bandit20) gid=11019(bandit19)
id -u     # 默认显示 euid（有效身份）
id -ru    # 显示 ruid（真实身份）
```

euid 只在**本次进程**内有效，程序一退出身份就恢复 —— 这正是 `/usr/bin/passwd` 能让普通用户临时写 `/etc/shadow`，又不会让他一直持有 root 的原因。Bandit 的 **Level 19→20**（`bandit20-do`）用的是完全同一套机制。
